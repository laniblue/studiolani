# 기획 모드 — 계정에서 시작하는 쇼츠 (대표님 지시 2026-10-22: reels-maker 흐름을 쇼츠에도)

내 채널 → 비슷한 채널 → 터진 쇼츠(100만+) → 분석 → 인사이트·주제 추천 → 원고(plan.json) → 제작.
결과는 작업 폴더 `/Users/hyuna/스튜디오 라니_콘텐츠/shorts/기획/<날짜>/` 안에 쌓는다. 중간에 끊겨도 파일에서 이어서 한다.

## 언제 이 모드로 가나
- 대표님이 **채널·계정 핸들**(유튜브 @채널, 인스타 @핸들, 틱톡 @핸들)만 주고 "쇼츠 기획", "쇼츠 주제 추천", "내 채널로 쇼츠"라고 할 때.
- 쇼츠 링크나 영상 파일을 주면 이 모드가 아니다 → SKILL.md 기본 흐름(링크에서 시작).
- 핸들이 없으면 한 번만 묻는다: "분석할 내 쇼츠 채널(@핸들)과 만들 언어(한국어/일본어)를 알려주세요."

## 원칙 (reels-maker와 같다)
- **숫자를 지어내지 않는다.** 화면에서 못 본 조회수·날짜·출처는 "확인 못 함".
- **영상은 직접 본다.** 제목만 보고 판단하지 않는다. 프레임 시트(`assets/yt-frames.js`)와 대본을 본다.
- **원문 그대로.** 제목·첫 문장·박힌 자막은 요약하지 않고 인용한다.
- **근거를 붙인다.** 패턴마다 "N편 중 M편", 추천마다 근거 쇼츠 링크.
- **무료만.** 브라우저 화면으로 보는 유튜브·인스타·틱톡 검색만 쓴다. vidIQ·Apify·Firecrawl 등 유료 도구는 대표님이 그 건만 허락했을 때만.

## 안전 규칙
- 사람처럼 화면으로만 본다. 내부 API를 직접 부르지 않는다. 페이지 이동마다 3~5초, 채널 하나 끝나면 1분 쉰다. 검색은 15번까지, 채널은 10개까지.
- 좋아요·구독·팔로우·댓글·저장·공유·DM은 누르지 않는다. 로그인·비밀번호 입력·설정 변경도 하지 않는다.
- 보안 확인·로그인 요구·"잠시 후 다시 시도"가 뜨면 즉시 멈추고 모은 것을 저장한 뒤 어디까지 했는지 알린다.

## 1. 내 채널 분석 → 카테고리  (`내채널.md`)
- 채널 이름·소개글 원문, 구독자·영상 수
- 쇼츠 탭 최근 약 30개: 반복 소재 3~5개, 형식(원본 각색·자막 중심·말하는 얼굴 등), 언어
- 조회수가 보이면 잘 된 것 3개·안 된 것 3개 (조회수는 화면에 보인 그대로)
- 정하기: **카테고리 1줄 · 타깃 1줄 · 검색 키워드 3~5개**(만들 언어로. 일본어 제작이면 일본어 키워드도)
- 3줄로 보여 주고 바로 2단계로 간다(틀렸다고 하면 고쳐서 다시).

## 2. 비슷한 채널 찾기  (`채널목록.csv`)
- 찾는 나라: **일본어로 만들 땐 일본·한국, 한국어로 만들 땐 미국·일본** (대표님 규칙).
- 키워드로 검색 → 채널을 모으고, 채널 이름·소개에서 겹치는 키워드로 다시 검색한다. 새 채널이 거의 안 나오거나 검색 15번이면 멈춘다.
- 고르기: 같은 카테고리 · 최근 3개월 안에 쇼츠를 올린 채널. 뉴스·연예인 공식·업종 밖은 빼고 이유 한 줄.
- **10개**까지. 기록: `핸들 | 나라 | 구독자 | 영상 수 | 찾은 키워드`

## 3. 터진 쇼츠 모으기  (`수집목록.csv`)
- 채널마다 쇼츠 탭 목록에 보이는 조회수를 읽는다(하나씩 열지 않는다).
- 기준: **조회수 100만 이상만** (대표님 규칙). 최근 1년 우선.
- 채널당 최대 3개, 전체 20개까지.
- 기록: `링크 | 채널 | 조회수 | 올린 날짜 | 원본 출처(元動画·크레딧) 또는 "확인 못 함"`
- **100만+가 10개 미만이면** 기준을 낮추지 않는다. 키워드 검색 결과에서 100만+ 쇼츠를 더 찾고, 그래도 부족하면 모인 개수 그대로 진행하며 "N개만 찾음"이라고 알린다.

## 4. 터진 쇼츠 분석  (`분석표.csv`)
상위 쇼츠를 직접 열어 프레임 시트로 보고(`assets/yt-frames.js`), 6가지로 뜯는다:
1. **훅** — 첫 2~3초의 화면/소리/글자. 헤더 제목 원문, 방식(질문·반전 예고·손해·비교·궁금증)
2. **소재·관점** — 누구의 이야기로 보여 줬나(원본과 관점이 어떻게 달라졌나)
3. **구조** — 구간표(몇 초 | 역할 | 내용), 끝맺음(반전·여운·되감기 유도)
4. **겉모양** — 상단 헤더·자막 위치·폰트·색 (`references/dynamic-edit.md`)
5. **편집** — 컷 수, 펀치인·기울기·플래시·스티커·효과음 위치와 빈도
6. **댓글 유도** — 문장 원문, 몇 초에

기록: `링크 | 조회수 | 헤더 제목 | 훅 방식 | 관점 | 길이 | 컷 수 | 편집 기법 | 원본 출처`
5개마다 진행 상황을 한 줄로 알린다.

## 5. 인사이트 + 주제 추천  (`리포트.md`, 오피스에는 결과만)
이 순서 그대로 보여 준다.

**① 이렇게 분석했어요** — 내 채널 카테고리 1줄 · 채널 N개 · 100만+ 쇼츠 N개(표: 채널 | 조회수 | 제목 | 링크)

**② 이런 결과가 나왔어요** — "N편 중 M편" + 원문 예시
- 자주 쓴 헤더 제목 틀 TOP 3
- 자주 쓴 관점 각색 방식·구조
- 조회수 상위와 나머지의 차이
- 아직 아무도 안 한 빈자리

**③ 내 쇼츠에 이렇게 반영하세요** — 3~5개. "지금은 ○○인데 → ○○로" 형식, 각각 근거 쇼츠 링크 1개.

**④ 이런 쇼츠를 만들어 보세요** — 5개. 주제마다:
`헤더 제목(2줄) | 쓸 훅 틀 | 각색 관점 | 왜 먹힐지(근거 편수) | 근거 쇼츠 | 원본 영상(틱톡·인스타 링크 또는 "확인 못 함") | 원본 이용: 출처 확인됨/확인 못 함`

끝은 반드시 이 말로:
> 위 주제 중 하나를 고르거나(번호), 직접 하고 싶은 주제를 알려 주세요.

## 6. 주제를 고르면 → 원고 → 제작
1. **원본 확보**: 원본(틱톡·인스타)을 찾아 보여 준다. 다운로드는 파일 이름·출처를 말하고 **대표님 허락을 받은 뒤에만**.
   - 원본 출처를 못 찾았으면 "확인 못 함"이라고 말하고 그 주제는 멈춘다(다른 쇼츠를 원본처럼 쓰지 않는다).
   - 다운로드 허락과 게시 권한은 다르다. 출처 표기(元動画)는 하지만, 원작자 이용 허락 여부는 확인 못 한 것으로 알리고 게시 판단은 대표님이 한다.
2. **원고 = plan.json** (SKILL.md ⚡ 빠른 자동 제작과 같은 형식, 그대로 호환). 주제를 고를 때 정한 헤더 제목·관점·훅 틀을 쓰고, 근거 쇼츠 링크를 `리포트.md` 원고 위에 적는다.
   - 제목·자막은 고른 출력 언어로(한국어/일본어). 해설/인물/속마음을 구분한다.
   - 해시태그에 `#面白い動画`(일본어) / `#웃긴영상`(한국어) 항상, 설명에 출처 `元動画: <원본 링크>`.
   - 배경음악 없음, 효과음 있음, 음성 없음.
3. **제작**: `quick-shorts.py`로 만든다 → 프레임 몇 장 확인 → `final-video.mp4`·`thumbnail.png`.
4. 업로드는 대표님이 직접 한다. 만들어서 오피스에 두기까지만.

## 자주 하는 실수
- 내 채널 분석을 건너뛰고 바로 검색 → 카테고리가 틀리면 전부 틀린다.
- 100만 미만을 "터졌다"고 넣기 → 넣지 않는다.
- 제목만 읽고 분석 → 프레임 시트를 보고 쓴다.
- 원본 출처를 못 찾았는데 다른 쇼츠를 원본처럼 쓰기 → 멈추고 알린다.
- 오피스 화면에 분석 과정(측정값·편집 목록) 띄우기 → 결과만.
